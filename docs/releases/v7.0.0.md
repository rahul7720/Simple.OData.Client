Simple.OData.Client 7.0.0 is a ground-up modernization of the library: one package for .NET 10 and C# 14, built on Microsoft.OData.Core 9, supporting OData V4 and V4.01 only, with the complete OData 4.01 feature set.

## Highlights

- **.NET 10 and C# 14 only.** A single `Simple.OData.Client` package replaces `Simple.OData.Client.Core` and the V3/V4 adapter packages. Nullable annotations are enabled and the library builds with the latest recommended analyzers and warnings as errors.
- **OData 4.01 end to end.** `$compute`, `$apply` aggregation, `$each` bulk update and delete, delta links and delta payloads, JSON batch, `respond-async` with status-monitor polling, `odata.maxpagesize` paging, key-as-segment URLs, CSDL JSON metadata, `omit-values=nulls`, instance annotations, `in`, `has`, `isof`/`cast`, `$search`, `$index`.
- **Modern API shape.** Every operation takes an optional `CancellationToken`, collection results are `IReadOnlyList<T>`, `FindEntriesAsAsyncEnumerable` follows every page, `GetMetadataAsync` returns an `IEdmModel`, `WebRequestException.Error` carries the parsed OData error, and a built request can be inspected and re-run.
- **Verified against a real server.** More than 500 end-to-end scenarios run against an in-process ASP.NET Core OData 4.01 service; opt-in live tests cover the public services.odata.org endpoints; a BenchmarkDotNet suite records the baseline.

## Install

The packages are attached to this release. Add the `.nupkg` to a local or private feed, then:

```bash
dotnet add package Simple.OData.Client --version 7.0.0
```

## Breaking changes

- OData V1 to V3 services, the adapter packages, `netstandard2.0` and `net461` targets are no longer supported.
- Removed: `ODataClientSettings.PayloadFormat`, `RenewHttpConnection`, `AdapterFactory`, `UseAbsoluteReferenceUris`, `WithExtensions()` (call `Apply` directly).
- URLs keep apostrophes literal (`Products(ProductName='Chai')`), collection members are unlinked with a key segment (`Categories(1)/Products(2)/$ref`), and complex function arguments travel as JSON parameter aliases.
- Inside a batch a `404` fails the batch unless `ContinueOnError` is set; `IgnoreResourceNotFoundException` applies to direct requests only.
- Undeclared properties no longer fail a read by default; set `Validations = ValidationKinds.All` to restore the old behaviour.

See "Migrating from 6.x" in the README for the full list.
